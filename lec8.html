马尔可夫决策过程(Markov Decision Process)

马尔可夫决策过程(Markov Decision Process，MDP)：一种数学框架，用于描述具有随机性和决策的序贯过程。在MDP中，我们考虑一个智能体与环境进行交互的情况，智能体根据环境的状态和奖励来做出决策，以最大化长期累积奖励。

MDP的要素定义如下:

  • 状态空间（State Space）：定义系统可能处于的所有状态s的集合S，即s ∈ S
  • 动作空间（Action Space）：定义智能体可以执行的所有可能动作a的集合A，即a ∈ A
  • 转移函数 （Transition Function）：描述系统在执行某个动作后从一个状态转移到另一个状态的概率 T(s, a, s’)/P(s’| s, a)
  • 奖励函数（Reward Function）：定义智能体在每个状态下执行某个动作后获得的即时奖励，表示为R(s, a, s’)
    • 有时候奖励函数仅和状态有关，即R(s) 或 R(s’)
  • 起始状态
  • 终止状态（可选）

马尔可夫性

  • 马尔可夫性是指一个随机过程具有无记忆性的性质，即未来的状态只依赖于当前状态，与过去的状态无关。
  • MDP的马尔可夫性体现在状态转移过程中。具体来说，马尔可夫决策过程中的马尔可夫性质表示当前状态的未来发展只依赖于当前状态和当前所选择的动作，而与过去的状态序列无关。
  • 马尔可夫性使得马尔可夫决策过程具有记忆缺失的性质，即系统在做决策时只需考虑当前状态和动作，而不需要记住整个历史状态序列。这种性质简化了问题的建模和求解，使得在求解问题时可以使用值函数和策略来指导智能体做出最优决策。

例子：网格世界

    一个类似迷宫的问题

  • agent生活在一个网格中
  • 墙壁挡住了agent的路径

    • 不完全理想的移动：动作并不总是按计划进行

  • 80%的时间，向北行动会使agent向北移动（如果那里没有墙）
  • 10%的时间，向北行动会使agent向西移动；10%向东移动
  • 如果agent应该走的方向有墙壁，agent会原地不动

    • agent会收到奖励

  • 每一步都有小的“生存”奖励（可以是负数），根据是正数或负数，会称为生存奖励(living reward)或生存惩罚(living penalty)
  • 大的奖励会在最后出现（好的或坏的）。

    • 目标：最大化奖励总和

策略

对于MDPs，我们希望一个最 π* : S → A

  • 一个策略π为每个状态提供一个动作
  • 最优政策是一种如果遵循就能最大化预期效用的政策
  • 显式策略定义了一个反射agent

例子：竞速

定义：

  • 一个机器人汽车想要快速地行驶远距离
  • 状态: Cool, Warm, Overheated
  • 动作: Slow, Fast
  • 行驶更快可以获得双倍奖励

任何马尔可夫决策过程都定义了一棵搜索树。因此，如果你处于某个特定状态，例如汽车处于Cool状态，你有两个动作可选：Slow或Fast。

每个马尔可夫决策过程状态都对应着一个类似期望最大化搜索树。

但在期望最大化算法中的工作量过大，其问题如下：

  • 重复状态过多
  • 搜索树是无穷的

为解决这个问题，我们先来了解效用。

效用(Utilities)

最大期望效用原则：一个理性的智能体应该根据其知识选择最大化其期望效用的行动。

引入效用的作用：

  • 在最坏情况极小化推理中，终端函数的比例不影响最终结果
    • 我们只是希望更好的状态能够获得更高的评价（正确排序）
    • 在决策过程中，效用函数对于结果的相对顺序保持不变（单调变换的不敏感性）
  • 对于平均情况下的期望最大化推理，效用可以帮助确保数值的大小有意义

效用函数是从结果（真实状态）到实数的函数，用来描述一个智能体的偏好。

定理：任何“理性(rational)”的偏好(preference)都可以被总结为一个效用函数。

  • 在游戏中，效用函数可以是简单的（+1/-1）
  • 效用函数总结了智能体的目标

我们硬编码效用函数，让行为自发产生。

  • 为什么我们不让智能体选择效用函数呢？
    • 以吸尘器为例：智能体可能想什么都不做，因此什么都不做是很容易的
  • 为什么我们不规定行为呢？
    • 这样做很难完全定义，复杂且依赖于具体情境

在马尔可夫决策过程（MDP）中，奖励是逐步到来的，我们需要弄清楚我们的效用函数实际上是什么。在最简单的情况下，你只需要将奖励相加，但情况可能比这更微妙。

智能体对奖励序列应该有什么偏好？更多还是更少？现在还是以后？

我们使用折扣因子(discount)来表达对奖励序列的偏好。

折扣法

在现实生活中，奖励总和最大化是合理的。而且更偏好即刻奖励而非延后奖励也是合理的。基于以上的考量，折扣法的解决方案是：奖励价值按指数衰减 。

折扣法具体指什么？

  • 每次我们降一个级别，我们都要乘以一个折扣因子

为什么使用折扣法？

  • 较早的奖励可能比较晚的奖励具有更高的效用
  • 有助于我们的算法收敛

如果智能体现在更喜欢A而不是B，那么它将来也应该更喜欢A而不是B，反之亦然。

  • Theorem：如果我们假设偏好是稳定的：
    • [a₁,a₂,...] ≻ [b₁,b₂,...] <=> [r, a₁,a₂,...] ≻ [r, b₁,b₂,...]
  • Then：定义效用函数只有两种方式
    • 加法效用(Additive utility): U( [r₀,r₁,r₂,...] ) = r₀ + r₁ + r₂ + ...
    • 折扣效用(Discounted utility): U( [r₀,r₁,r₂,...] ) = r₀ + γ·r₁ + γ²·r₂ + ...

解决MDPs

在“示例：赛车MDP”中，我们提出了两个问题，现在可以给出解决这些问题的思路:

  • 重复状态过多
    • Idea: 只计算一次所需的数量
  • 搜索树是无穷的
    • Idea:做一个深度有限的计算，但随着深度的增加，直到变化很小
    • 注意: 如果γ < 1，树的深处最终不重要
最优数量
  • 状态s的值(效用)为:
    • V*(s) = 期望效用，从s开始并以最优方式运行
    • *号代表这是在最优行动下的价值。
  • q-state (s,a)的值(效用):
    • Q*(s,a) = 期望效用开始时从状态s中采取行动a，然后(此后)采取最佳行动
    • 每个行动都有一个Q值
  • 最优策略：
    • π*(s) = 状态s的最优行为

  • 是指如果游戏在接下来的 k 步结束，状态 s 的最优值。
  • 等价地，这就是从状态s开始进行深度为k的expectimax搜索所得到的结果。

  • 重复进行直到收敛，得到 V*

  • 定理：会收敛到单一最优解

对比总结

  • 价值迭代和策略迭代都计算相同的内容（所有最优值）。
  • 价值迭代：
    • 每次迭代都会更新值和（隐式地）策略。
    • 我们不跟踪策略，但通过对动作取最大值隐式地重新计算策略。
  • 策略迭代：
    • 我们进行多次遍历，使用固定策略更新效用值（每次遍历都很快，因为只考虑一个动作，而不是所有动作）。
    • 在策略评估完成后，选择一个新策略（类似于进行值迭代遍历的速度）。
    • 新策略将会更好（或者已经完成）。
  • 两者都是解决MDP的动态规划方法
  • 为什么要选择价值迭代？
      • 价值迭代更简单，在动作数量较少的情况下可能会选择这种方法。
